## 2. 关键技术点

### 2.1 序列化集成 Protobuf & JSON

- **Protobuf**：采用 Google Protocol Buffers 作为主力序列化方案，适用于高性能、强类型的二进制通信。通过 `.proto` 文件定义消息结构，自动生成 C++ 代码，极大简化了数据结构的维护与升级。
- **JSON**：用于配置文件或简单通信场景，便于人类阅读和调试。集成如 `nlohmann/json` 等现代 C++ JSON 库，实现对象与 JSON 字符串的高效互转。
- **集成方式**：在消息收发流程中，增加序列化/反序列化步骤。发送前将对象序列化为二进制或 JSON 字符串，接收后反序列化为 C++ 对象，便于后续业务处理。

#### 示例代码片段

```cpp
// Protobuf 序列化
MyProtoMsg msg;
msg.set_id(123);
msg.set_content("hello");
std::string out;
msg.SerializeToString(&out);

// JSON 序列化
nlohmann::json j = {{"id", 123}, {"content", "hello"}};
std::string json_str = j.dump();
```

---

### 2.2 逻辑层与网络层解耦

- **架构设计**：采用“网络层负责通信，逻辑层负责业务”的分层思想。网络层只负责收发原始数据包，收到完整消息后将其转发给逻辑层处理，逻辑层处理完毕后再通过网络层发送响应。
- **实现方式**：引入 `LogicSystem` 单例类，作为业务逻辑的统一入口。网络层通过回调或消息队列将数据推送给逻辑层，逻辑层无需关心底层通信细节。
- **优点**：
  - 降低模块耦合度，便于单元测试和后续功能扩展。
  - 支持多种协议/序列化方式的灵活切换。

#### 架构示意

```
[网络层] <----> [消息队列/回调] <----> [逻辑层(LogicSystem)]
```

---

### 2.3 优雅退出机制（信号处理）

- **需求背景**：服务器运行过程中，需支持通过 Ctrl+C 或 kill 信号安全关闭，避免数据丢失或资源泄漏。
- **实现方式**：
  - 使用 Boost.Asio 的 `signal_set` 监听 SIGINT/SIGTERM 等信号。
  - 捕获信号后，优雅停止 `io_context`，等待所有异步操作完成后安全退出。
- **效果**：保证服务器在接收到退出信号时，能正确释放资源、保存必要状态，提升系统健壮性。

#### 关键代码片段

```cpp
boost::asio::signal_set signals(io_context, SIGINT, SIGTERM);
signals.async_wait([&](auto, auto){
    std::cout << "收到退出信号，正在优雅关闭..." << std::endl;
    io_context.stop();
});
```
